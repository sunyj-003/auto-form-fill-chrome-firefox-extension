# Workflow Confirm Skill

用户确认工作流：讨论需求 → 验收标准 → AI实现 → AI自检 → 人工确认。

## 何时使用

当用户描述以下场景时，激活此 skill：
- "先讨论需求"、"聊聊这个功能怎么做"
- "建立验收标准"、"什么是完成的标准"
- "交给 AI 实现"、"帮我实现这个"
- "AI 校验"、"检查是否符合标准"
- "人工确认"、"你确认一下"、"最后检查"

## 工作流阶段

### 阶段 1：讨论需求 (Discussion)

**目标**：理清要做什么，明确问题边界。

**执行步骤**：
1. 主动询问用户更多细节
2. 理解业务背景和用户期望
3. 识别可能的问题和歧义
4. 整理成清晰的需求描述

**输出格式**：
```
## 需求理解

### 功能描述
[简短描述]

### 关键点
- [ ] 关键点1
- [ ] 关键点2

### 待确认问题
1. 问题1？
2. 问题2？
```

### 阶段 2：建立验收标准 (Define Acceptance)

**目标**：明确"什么算完成"，创建可验证的标准。

**执行步骤**：
1. 将需求拆解为具体可验证的检查项
2. 每个检查项必须是客观可验证的
3. 包含功能性标准 + 质量标准
4. 用 Markdown 复选框格式列出

**验收标准模板**：
```markdown
## 验收标准

### 功能性标准
- [ ] 标准1（具体描述）
- [ ] 标准2（具体描述）

### 质量标准
- [ ] 代码无明显错误
- [ ] 通过测试/构建

### 边界情况
- [ ] 处理边界情况X
- [ ] 处理边界情况Y
```

### 阶段 3：AI 实现 (Implementation)

**目标**：根据验收标准实现功能。

**执行步骤**：
1. 按 TDD 方式先写测试/验证代码
2. 实现功能直到满足验收标准
3. 遇到问题及时记录并反馈给用户
4. 完成后进行自检

**关键约束**：
- 不要创建不必要的文档文件
- 遵循项目现有的代码风格
- 保持实现简单，满足需求即可

### 阶段 4：AI 自检 (Self-Verification)

**目标**：对照验收标准检查实现是否符合要求。

**执行步骤**：
1. 读取阶段 2 建立的验收标准
2. 逐项检查实现是否满足每个标准
3. 对每项标准给出 PASS/FAIL 判断和证据
4. 如有 FAIL 项，返回阶段 3 继续修复
5. 全部 PASS 后，进入人工确认

**输出格式**：
```
## 自检报告

| 验收标准 | 状态 | 证据 |
|---------|------|------|
| 标准1   | ✅   | 实现已包含X功能 |
| 标准2   | ❌   | 缺少Y功能 |

结论：[全部通过 / 有X项未通过，需要修复]
```

### 阶段 5：人工确认 (Human Approval)

**目标**：人类最终检查，确认通过。

**执行步骤**：
1. 总结已完成的工作
2. 展示关键变更内容
3. 明确告知需要检查的点
4. 等待用户确认

**输出格式**：
```
## 待人工确认

### 已完成
- 功能实现：XXX
- 代码质量：已自检通过
- 测试覆盖：XXX

### 请检查
1. [检查点1]
2. [检查点2]

### 下一步
请回复"确认"表示通过，或提出需要修改的地方。
```

## 状态流转

```
用户 → [讨论需求] → [建立验收标准] → [AI实现] → [AI自检] → [人工确认] → 完成
                                    ↓                              ↓
                              [不符合标准]                        [需要修改]
                                    ↓                              ↓
                              返回AI实现 ←────────────────── 返回AI实现
```

## 关键原则

1. **每个阶段明确输出**：每个阶段必须有明确的产物，用户可以评估
2. **验收标准可执行**：标准必须具体、可验证，避免模糊描述
3. **自检必须对照标准**：AI 自检时必须逐项对照阶段 2 的标准检查
4. **人工确认前自检**：人工确认前必须先完成 AI 自检，确保基本质量
5. **迭代直到通过**：未通过自检则继续迭代，直到满足所有标准

## 与其他工具集成

- **planner agent**：在讨论需求后可使用，帮助拆解任务
- **tdd-guide**：实现阶段使用，确保测试驱动
- **code-reviewer**：实现后使用，进行代码审查
- **verification-loop**：自检阶段使用，进行自动化验证
